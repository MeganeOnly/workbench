# 我的工作台（Workbench）

本地网页版工作台：把常用操作做成按钮，点一下即执行。**零依赖**（纯 Node 内置模块 + 原生前端，无构建步骤），仅监听本机。

- 访问地址：`http://127.0.0.1:3180`（仅本机可访问）
- 启动方式：双击 `start-workbench.bat`，自动清理旧进程、后台启动服务并打开浏览器
- 快速上手：复制 `buttons.example.json` 改名为 `buttons.json`，按需改成你自己的程序路径即可（所有按钮纯配置驱动，无需改代码）；涉及本机路径的可选配置见下方「个人配置」

## 特性一览

- **按钮墙**：功能按钮与信息卡混排，点击卡片任意位置执行、按住拖动换位
- **多种布局与外观**：3 种布局（Bento 网格 / 控制台列表 / 双栏仪表盘）× 9 套外观主题，即时生效自动保存
- **状态徽章**：按钮按端口 / 进程实时显示「运行中 / 已停止」
- **模式系统**：工作 / 娱乐 / 投资等多模式，内容可按模式显隐（含只读模式）
- **系统信息卡**：DeepSeek 余额、系统状态、DSH 对话、书签、滴答今日任务 / 专注、MiniMax 套餐、RSS 订阅、投资计算器
- **顶栏快速搜索**：实时过滤卡片与书签，回车执行、按 `/` 聚焦
- **DeepSeek 峰谷定价提醒**：高峰时段脉冲提醒 + 剩余时长，空闲时段显示半价
- **自动添加快捷方式**：填程序路径（.exe / .lnk）即生成卡片，自动提取图标、自动配启动 / 激活逻辑，全程不消耗 token

## 个人配置（config.json，可选）

部分功能依赖本机路径（凭据文件、工作目录等）。把这些路径写进 `config.json`（参考 `config.example.json`，该文件已被 .gitignore 排除，不会误提交）：

| 键 | 作用 | 不配置时的表现 |
|---|---|---|
| `ankiQueuePath` | Anki 待推送队列 JSON 路径 | Push 卡显示"队列文件不存在" |
| `credentialsPath` | 含 `DEEPSEEK_API_KEY` 的 yaml 路径 | 余额卡显示"未找到 DEEPSEEK_API_KEY" |
| `didaMcpConfig` | 滴答清单 MCP 的 Bearer token 所在配置 | 今日任务/专注卡获取失败 |
| `pushCwd` | Push 按钮新建 DSH 对话的工作目录 | 回退到 `didaDefaultCwd` |
| `didaDefaultCwd` | dida 按钮新建 DSH 对话的工作目录 | 回退到用户主目录 |
| `minimaxWeeklyHourlyRatio` | MiniMax 周限额按小时换算比例 | 使用默认比例 |

不配置任何一项也能启动，对应功能优雅降级（显示原因，不影响其他卡片）。

### 卡片墙（Bento 布局）

中间区域是 **8 列 Bento 卡片墙**：功能按钮与信息卡混排。**点击卡片任意位置即可执行**（功能卡）；**按住卡片任意位置拖动**即可换位（轻点与拖动自动区分，顺序保存在浏览器 localStorage 中，刷新后保留）。

- 内置信息卡：**DeepSeek 余额**（点击跳转用量页）、**系统状态**（DSH 3080 / 工作台 3180）、**DSH 对话**（对话状态可视化）、**书签**（卡片右上角 **+** 可直接添加网页；侧栏与书签卡内的书签都可**按住任意位置拖拽排序**，顺序保存在服务端）、**滴答今日任务**、**滴答专注**、**MiniMax 套餐**（周限额进度）、**RSS 订阅**（见下）、**投资计算器**（见下）
- 卡片尺寸档位：`size: "large"`（半行 4 列）/ `"wide"`（半行 4 列）/ `"small"`（四分之一行 2 列），不写默认 `wide`
- 小屏自动降为 2 列 / 1 列
- 样式面板「布局」区有**侧边栏开关**：可随时启用/禁用书签管理侧栏（禁用后仍可通过书签卡的 + 添加书签）

### 模式系统

顶栏有模式切换器，内容（书签 / RSS 源 / 快捷方式 / 手动按钮 / 系统卡）可按模式显隐。默认模式定义在 `modes.json`：

| 模式 | 说明 |
|---|---|
| 工作 | 默认，只读（除模式切换外禁止改动卡片/书签/RSS） |
| 娱乐 | 可自由编辑 |
| 投资 | 只显示投资计算器 |

- 设置面板「模式管理」区可给任意内容（书签 / RSS / 快捷方式 / 手动按钮 / 系统卡）配置可见模式（multi-tag 多选），或设为「隐藏」
- 新增模式只需在 `modes.json` 追加一条 `{id, name, icon, readonly}`，前端切换器自动渲染，零代码改动

### 投资计算器

「投资」模式下显示的投资计算器卡，目标权重 / 当前持仓 / 推荐定投 / 再平衡。支持**自加/删标的**（目标与持仓两列表动态化），每日定投按缺口比例分配，再平衡计算带软约束提示。

### 顶栏快速搜索

顶栏搜索框：输入关键字**实时过滤**卡片墙与侧栏书签（按名称/描述/网址匹配），**回车**执行顺序中第一个匹配（功能卡 = 点击执行，书签 = 打开网页），**Esc** 清空恢复。按 **/** 键可随时聚焦搜索框。不需要可在「样式 → 偏好 → 搜索框」一键关闭。

### RSS 订阅卡

「样式 → RSS 订阅」区可添加任意 RSS / Atom 订阅源（名称 + 地址），卡片上按源分组显示最新条目（每源 8 条，点击标题打开原文；点击源名打开源站点）。适合订阅文献更新（如 arXiv 分类源 `http://export.arxiv.org/rss/cs.AI`，把 `cs.AI` 换成你的方向）或博客/资讯。

- 服务端每 15 分钟缓存一次抓取，前端 10 分钟刷新；单源抓取失败自动沿用上次内容并淡化显示
- 最多 12 个源；不需要整个卡片时在「偏好 → RSS 订阅卡」一键关闭（关闭后不抓取）

### DeepSeek 峰谷定价提醒

顶栏右侧有**时段指示器**：高峰时段（北京时间 9-12 / 14-18）显示橙色「高峰价 · 剩余 X 小时 Y 分」并带脉冲动画；空闲时段显示绿色「空闲价 · 半价」。Push 卡片在高峰时段额外显示费用提醒行。判定基于本机时间，每分钟自动刷新。

### Push 卡片工作原理

点击"Push 卡片"后，工作台通过 dsh web 的本地 API（127.0.0.1:3080）执行两步：

1. `session.create` — 在 `config.json` 的 `pushCwd` 目录创建一个全新对话
2. `session.prompt` — 向该对话发送 `push anki 卡片`，触发 anki-card-push skill 流程

完成后自动打开 DSH 页面，你会在会话列表顶部看到最新创建的 push 对话（状态为执行中）。每次点击都是全新对话，天然满足"一个对话最多三次、多了换新"的需求——每次 push 都是干净的上下文。

## 如何新增按钮（后续需求扩展）

编辑 `buttons.json`，在 `buttons` 数组中追加一项即可，无需改动代码。

### 普通按钮

```json
{
  "id": "my-tool",
  "name": "我的工具",
  "description": "按钮说明",
  "size": "small",
  "command": "cmd.exe",
  "args": ["/c", "call \"C:\\path\\to\\script.bat\""],
  "port": 3080,
  "color": "#10b981"
}
```

字段说明：

- `id`：唯一标识（URL 使用）
- `name` / `description`：界面显示
- `size`：可选，卡片尺寸 `large` / `wide` / `small`，默认 `wide`
- `command` / `args`：要执行的命令。执行 .bat 一般用 `cmd.exe /c call "..."`，窗口自动隐藏
- `port`：可选，填端口号后按钮会实时显示该端口"运行中/已停止"
- `process`：可选，填进程名后按钮会实时显示该程序"运行中/已停止"（前缀匹配，实际进程名可带后缀；「快捷方式」面板添加 .exe/.lnk 时自动配置，.lnk 会解析出真实目标进程，如滴答清单 → `TickTick.exe`）
- `color`：按钮颜色，任意十六进制色值

### 切换按钮（toggle，按状态变色）

适合"启动/停止同一个服务"的场景：一个按钮根据端口状态自动显示对应动作并变色。

```json
{
  "id": "my-service",
  "name": "我的服务",
  "description": "点击启动或停止",
  "port": 3000,
  "toggle": {
    "start": {
      "label": "启动服务",
      "color": "#047857",
      "command": "cmd.exe",
      "args": ["/c", "call \"C:\\path\\to\\start.bat\""]
    },
    "stop": {
      "label": "停止服务",
      "color": "#dc2626",
      "command": "cmd.exe",
      "args": ["/c", "call \"C:\\path\\to\\stop.bat\""]
    }
  }
}
```

字段说明：

- `port`：必填，根据该端口是否监听自动决定执行 `start` 还是 `stop`
- `toggle.start` / `toggle.stop`：各自包含 `label`（按钮文字）、`color`（按钮颜色）、`command` / `args`（执行的命令）

修改保存后，刷新工作台页面即可看到新按钮。

## 开发说明（给想改代码的人）

本项目迭代中沉淀了几条关键工程约定，改代码前必读：

- **bat 文件必须纯 ASCII**（注释写英文）：cmd.exe 按系统 OEM 代码页解析批处理，UTF-8 中文注释会吞掉换行符导致命令错乱甚至挂起。
- **执行命令用「字符串拼接 + `spawn(shell: true)`」**，不能用参数数组形式：数组形式会对含引号参数二次转义，cmd 无法解析（表现为按钮无反应、退出码 1）。
- **按钮点击必须有可见反馈**（全局 toast 已实现）；新增按钮类型必须保持。
- **前端点击接线单一真源 `rec.current`**：点击监听器与渲染赋值必须共用同一对象属性，曾因读写两个不同属性导致点击静默失效（零请求零报错）。改卡片逻辑后必须跑 `node tests/test-click.mjs`（无头浏览器回归测试）。
- **静态文件响应带 `Cache-Control: no-cache`**；`/api/buttons` 返回前端文件 MD5 版本号，页面轮询发现版本变化自动 reload——根治"改了代码但用户停在旧标签页"。
- **打开外部链接用 `openExternal(url)`**（新标签页优先、被拦截回退当前页跳转），禁止直接 `window.open`。
- **改 `buttons.json` / `public/` 静态文件刷新页面即生效**（配置 1 秒 TTL 自动重载）；只有改 `server.js` 才需重启服务。
- **前端多文件拆分**：业务逻辑按职责拆到 `wb-*.js`（core/mode/state/render），跨文件调用统一挂到 `window.WB` 命名空间；新增文件见 HACKING.md §2。
- **数据加载失败必须显式告警 + 拒绝覆盖**：用户数据文件（如 `bookmarks.json`）加载失败时备份原文件并挂起写入，防止"内存空数组覆盖原文件"的数据丢失。

## 说明

- 工作台服务仅监听 `127.0.0.1`，不会对外网开放。
- 手动启动服务：在 `workbench` 目录执行 `node server.js` 即可。
- 运行记录仅保存在内存中，工作台服务重启后清空。
